# 微信小程序上架（可行性 + 三种路线）

## 结论先说

**能上，但不建议把这个 16 门语言的阅读器"重写"成原生小程序。** 三条路线，按成本排序：

| 路线 | 工作量 | 费用 | 体验 | 建议 |
|---|---|---|---|---|
| **A. web-view 套壳** | 0.5 天 | 0（需企业主体） | 与网页版一致 | ⭐ 推荐先做 |
| B. 原生重写（WXML/WXSS/JS） | 15–30 人日 | 0 | 最流畅 | 有收入后再做 |
| C. uni-app / Taro 转译 | 8–15 人日 | 0 | 中等 | 折中 |

---

## 一、硬门槛（先确认你能不能过）

| 项 | 要求 | 说明 |
|---|---|---|
| **主体** | **必须企业**（个人主体不能选"教育"类目） | 个人号可选类目极少，阅读类基本不行 |
| **ICP 备案** | 小程序要备案（2024 起强制） | 需要域名 + 服务器，备案 7–20 天 |
| **类目** | 教育 → 在线阅读 | 需提供《网络出版服务许可证》或说明为公版内容 |
| **内容合规** | 书籍必须公版或已授权 | 我们的书全部来自 Project Gutenberg / 青空文库，可举证 |
| **不能有外部支付** | 小程序内只能用微信支付 | 虚拟商品必须走微信支付，且 iOS 端**禁止**虚拟支付（微信规则） |
| **web-view 域名** | 必须在小程序后台配置业务域名，且**域名需备案** | 这是套壳路线的关键卡点 |

> ⚠️ iOS 端小程序**不能用微信支付买虚拟内容**（微信 & Apple 双重限制）。所以小程序更适合做"免费阅读 + 引流到 App/网页版开通会员"。

## 二、路线 A：web-view 套壳（推荐）

### 目录结构

```
weapp/
├── app.js
├── app.json
├── app.wxss
├── project.config.json
└── pages/
    └── web/
        ├── web.js
        ├── web.json
        ├── web.wxml
        └── web.wxss
```

### app.json

```json
{
  "pages": ["pages/web/web"],
  "window": {
    "navigationBarTitleText": "LIZZREAD",
    "navigationBarBackgroundColor": "#0F8A4D",
    "navigationBarTextStyle": "white"
  },
  "sitemapLocation": "sitemap.json"
}
```

### pages/web/web.wxml

```xml
<web-view src="{{url}}" bindmessage="onMessage" binderror="onError"></web-view>
```

### pages/web/web.js

```js
Page({
  data: { url: '' },
  onLoad(options){
    // 支持从分享链接带语言参数进来
    const lang = options.lang || 'en';
    const base = 'https://你的备案域名/LIZZREAD/index.html';
    this.setData({ url: base + '?lang=' + lang + '&wx=1' });
  },
  onMessage(e){ console.log('web-view 消息', e.detail); },
  onError(e){ wx.showToast({ title: '加载失败，请稍后再试', icon: 'none' }); }
});
```

### 必须做的适配（重要）

小程序 web-view 里没有 `localStorage` 的部分能力、也没有 Service Worker。需要在 `index.html` 里做兼容：

1. 检测 `navigator.userAgent.includes('miniProgram')`（微信 webview UA 含 `miniProgram`）
2. 该环境下：
   - **关闭 Service Worker 注册**（小程序不支持）
   - **storage 用 try/catch 包住**（部分 API 受限）
   - **翻译改走后端**（小程序不允许直连第三方域名，需域名白名单）
   - **下载/导入文件禁用**（小程序 web-view 不能选文件）
   - 顶部返回按钮交给小程序原生导航
3. 后端域名必须加到小程序的 **request 合法域名** 里

### 上线步骤

1. 注册企业小程序：https://mp.weixin.qq.com/ → 主体信息 → 企业认证（¥300/年认证费）
2. 完成 **ICP 备案**（小程序备案入口在后台）
3. 后台 → 开发 → 开发设置 → **业务域名** 添加你的站点域名（需上传校验文件到站点根目录）
4. 下载微信开发者工具：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
5. 导入 `weapp/` 目录 → 填 AppID → 上传
6. 后台 → 版本管理 → 提交审核（1–7 天）

## 三、路线 B：原生重写（成本最高）

小程序不支持直接跑现有 HTML/JS，需要：

- 用 WXML/WXSS 重写界面（书城、阅读器、弹窗、拼装…）
- 把 `index.html` 里的逻辑拆成小程序模块
- 词典 18MB 不能塞进小程序（主包 2MB、总包 20MB 限制）→ 必须放后端
- 全文书籍同理，必须放后端（小程序单次请求上限 10MB）

**结论**：等于重做一个 App，不建议现在做。

## 四、路线 C：uni-app / Taro 转译

- 用 uni-app 重写一遍，可同时输出小程序 + H5 + App
- 但阅读器的点词、分句、TTS 都需要重写
- 适合"以后要做多端"时一次性投入

## 五、给你的建议顺序

```
今天：PWA（已完成）
本周：Android APK 分发 + 华为上架
有收入后：Apple $99 → TestFlight → 上架
再做：微信小程序（企业主体 + 备案齐全后，用 web-view 套壳，0.5 天）
```

**小程序最大的价值不是变现**（iOS 端不能卖虚拟内容），而是**拉新**：用户在小程序里免费读，引导去 App/网页版开通会员。
