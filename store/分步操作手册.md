# ① PWA 网页版

## 1.1 现状（✅ 已完成）

**线上地址**：https://hcc9886.github.io/LIZZREAD/

- 部署方式：GitHub Actions，push 到 main 自动部署（`.github/workflows/pages.yml`）
- 更新方式：用户打开时自动检测，底部出现「🎉 有新版本可用 / 立即更新」
- Service Worker 缓存版本：`sw.js` 里的 `lizzread_v27`

## 1.2 让用户装到桌面（4 步）

### iPhone / iPad —— **必须用 Safari**

> ⚠️ 微信、QQ、钉钉里打开**装不了**，必须先复制链接到 Safari。

1. 打开 **Safari**，地址栏输入 `hcc9886.github.io/LIZZREAD`
2. 点屏幕**底部中间**的「分享 ⬆️」按钮
3. 弹出菜单**往下滑**，找到 **「添加到主屏幕」**，点它
4. 右上角点 **「添加」**

✅ 成功后：桌面出现绿色 LIZZREAD 图标，点开是**全屏**（没有浏览器地址栏），**可离线**。

### Android —— Chrome / 华为浏览器 / Edge

1. 打开链接
2. 底部会自动弹「把 LIZZREAD 装成 App」→ 点 **安装**
3. 如果没弹：右上角 **⋮** → 「安装应用」或「添加到主屏幕」

### 电脑 —— Chrome / Edge

地址栏最右侧出现 **⊕ 安装图标** → 点一下就装成独立窗口应用。

## 1.3 换自己的域名部署（可选）

### 方案 A：Vercel（最简单，免费）

```bash
cd ~/Desktop/LIZZREAD
npm i -g vercel
vercel login
vercel deploy dist-web --prod
```

失败就先构建：

```bash
bash scripts/build-web.sh     # 生成 dist-web/，约 730MB
vercel deploy dist-web --prod
```

✅ 成功后会得到一个 `https://xxx.vercel.app` 地址。

### 方案 B：Netlify（拖拽）

1. 打开 https://app.netlify.com/drop
2. 把 `dist-web` 文件夹**整个拖进去**
3. 等上传完成（730MB，约 5–15 分钟）

### 方案 C：Cloudflare Pages（国内访问较快）

1. https://dash.cloudflare.com/ → Workers & Pages → Create
2. 选 **Upload assets** → 上传 `dist-web`

### 方案 D：阿里云 OSS + CDN（国内最快，要钱）

1. 开通 OSS：https://oss.console.aliyun.com/
2. 新建 Bucket（地域选**华东1**或**华北2**），读写权限选**公共读**
3. 用 ossbrowser 上传 `dist-web` 里的全部内容
4. Bucket → 基础设置 → **静态页面** → 默认首页填 `index.html`
5. 开 CDN 加速 → 绑定你的域名 → 申请免费 SSL 证书

> 费用：存储 730MB 约 ¥0.09/月，流量另算（0.24 元/GB）。

### 方案 E：自己的服务器 + Nginx

```bash
scp -r dist-web/* user@服务器:/var/www/lizzread/
```

Nginx 配置：

```nginx
server {
    listen 443 ssl http2;
    server_name read.你的域名.com;
    root /var/www/lizzread;
    index index.html;

    ssl_certificate     /etc/letsencrypt/live/read.你的域名.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/read.你的域名.com/privkey.pem;

    location = /sw.js         { add_header Cache-Control "no-cache"; }
    location = /manifest.json { add_header Cache-Control "no-cache"; }
    location / { try_files $uri $uri/ /index.html; }
}
```

证书：`sudo certbot --nginx -d read.你的域名.com`

⚠️ **必须保留目录结构**：`covers/ data/ books/ sentences/ dicts/ shared/ reader/ vendor/`，少一个就 404。

## 1.4 发新版

```bash
cd ~/Desktop/LIZZREAD
# 1) 改 sw.js 里的缓存版本号（lizzread_v27 → lizzread_v28），这步必须做，否则用户拿不到新版
sed -i '' 's/lizzread_v27/lizzread_v28/' sw.js
# 2) 提交推送
git add -A && git commit -m "feat: xxx" && git push
```

Pages 会自动重新部署，2–5 分钟后用户打开就能看到「立即更新」。

## 2.2 发给用户（3 种方式）

**方式 1：微信传文件**
1. 电脑微信 → 文件传输助手 → 发送 `LIZZREAD-2.0.0-release.apk`
2. 手机微信打开 → 点文件 → 右上角 ⋯ → **用其他应用打开** → 安装
3. 提示「未知来源」→ 允许 → 安装

**方式 2：网盘**
把 APK 传到百度网盘 / 阿里云盘，生成分享链接发出去。

**方式 3：自己的后端直链**
部署后端后，用户访问 `https://你的域名/download/LIZZREAD.apk` 直接下载（这个路由已经在 `server.js` 里写好）。

## 2.3 应用内更新（✅ 已实现）

用户端：**设置 → 关于 → 🔄 检查更新**

- 有新版本 → 弹窗显示版本号 + 更新说明 + **「下载安装包」**按钮
- 点击 → 下载 APK → 系统安装器 → **覆盖安装，数据全保留**
- 已是最新 → 提示「已是最新版本 2.0.0」

> 我刚改好：现在静态托管（GitHub Pages）也能读到 `data/app-version.json` 做版本检查了，不依赖后端。

## 2.4 发新版（一条命令）

```bash
cd ~/Desktop/LIZZREAD

# 1) 升版本号（自动写 app-version.json + app-version.js）
node scripts/bump-version.js patch        # 2.0.0 → 2.0.1
# 也可以：node scripts/bump-version.js minor   # → 2.1.0
# 也可以：node scripts/bump-version.js 2.2.3   # 指定版本

# 2) 打包（读 app-version.json 自动写进 gradle）
./build-app.sh

# 3) 推送（用户端就能检查到更新）
git add -A && git commit -m "release: 2.0.1" && git push
```

产物自动出现在：
- `dist/LIZZREAD-2.0.1-release.apk`
- `dist/LIZZREAD-2.0.1.aab`
- `download/LIZZREAD.apk`（App 内更新用的固定路径）

## 2.5 ⚠️ keystore 备份警告（最重要）

| 项 | 值 |
|---|---|
| 文件 | `android/app/lizzread.keystore` |
| 别名 | `lizzread` |
| store 密码 | `lizzread2026` |
| key 密码 | `lizzread2026` |

**今天已自动备份到**：`.backup/lizzread-keystore-20261124.keystore` + `.backup/签名信息-务必保存.txt`

**丢失后果**：已安装的用户**无法覆盖升级**，只能卸载重装（进度、生词全部丢失），商店版本也无法更新。

**请你再做三件事**：
1. 把这个 keystore 复制到 **U 盘 / 网盘 / 密码管理器**
2. 密码单独记在密码管理器里（不要和 keystore 放同一个位置）
3. 绝对不要提交到公开仓库（`.gitignore` 里已经排除）

# ④ 微信小程序

## 4.1 三道门槛（⏳ 只有你能办）

| 门槛 | 要求 | 你能过吗 |
|---|---|---|
| **主体类型** | 必须**企业 / 个体工商户**。个人主体不能选「教育-在线阅读」 | ☐ |
| **ICP 备案** | 2024-09 起强制，需**已备案域名** | ☐ |
| **内容合规** | 书籍必须公版，需能举证 | ✅（Gutenberg 公版） |

## 4.2 工程在哪（✅ 已生成）

`weapp/` 目录，直接导入微信开发者工具即可。

```
weapp/
├── app.js              ← 改 SITE（你的已备案域名）
├── app.json
├── project.config.json ← 改 appid
├── sitemap.json
├── README.md
└── pages/web/          ← web-view 套壳页面
```

**只需改两处**：
- `weapp/app.js` 第 8 行：`SITE: 'https://你的域名'`
- `weapp/project.config.json` 第 18 行：`"appid": "wx你的AppID"`

## 4.3 九步上线

### 第 1 步：注册（10 分钟）
- https://mp.weixin.qq.com/ → **立即注册** → 选 **小程序**
- 用**没注册过公众号/小程序的邮箱**
- 收验证邮件 → 点链接激活

### 第 2 步：主体认证（1–3 天）
- 主体类型选 **企业**
- 填营业执照信息
- 对公账户打款验证（微信打一笔随机小额）
- 付 **¥300/年** 认证费
- 拿到 **AppID**（形如 `wx1234567890abcdef`）

### 第 3 步：域名备案（7–20 天，最慢）
- 买域名（阿里云/腾讯云 ¥30–60/年）
- 买国内服务器（轻量应用服务器 ¥60+/年）
- 在服务器提供商备案系统提交：主体信息 + 网站信息（服务内容选「其他-教育」）
- 管局审核 7–20 工作日

### 第 4 步：小程序备案
- 小程序后台 → **设置 → 基本设置 → 备案信息** → 去备案
- 填主体、负责人、服务内容（教育-在线教育）
- 上传营业执照、法人身份证、承诺书
- 审核 7–20 天

### 第 5 步：部署站点
```bash
cd ~/Desktop/LIZZREAD
bash scripts/build-web.sh
# 上传 dist-web/ 到你的服务器，必须开 HTTPS
```

### 第 6 步：配置业务域名（关键）
- 后台 → **开发 → 开发管理 → 开发设置 → 业务域名**
- 点「修改」→ 下载校验文件 `XXXXX.txt`
- 把文件放到网站根目录：`/var/www/lizzread/XXXXX.txt`
- 确认能访问：`https://你的域名/XXXXX.txt`
- 回后台填域名 → 保存

> ⚠️ 业务域名**每月只能改 3 次**。没配这一步，web-view 会白屏。

### 第 7 步：服务类目
- 后台 → **设置 → 基本设置 → 服务类目**
- 添加：一级 **教育**，二级 **在线阅读**
- 需要上传《公版作品说明》：
  > 本小程序内容全部为 Project Gutenberg（https://www.gutenberg.org）、青空文库等公有领域作品，作者逝世均已超过 70 年，不涉及版权问题。

### 第 8 步：上传代码
- 下载微信开发者工具：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
- 导入项目 → 选 `weapp/` → 填 AppID
- 点右上角 **上传** → 版本号 `2.0.0` → 备注

### 第 9 步：提交审核
- 后台 → **版本管理** → 找到刚上传的版本 → **提交审核**
- 审核备注建议写：
  > 本小程序通过 web-view 加载已备案域名的网页版阅读器。全部书籍为公有领域作品，无用户生成内容，无社交功能，无支付。
- 审核 **1–7 天** → 通过后点 **发布**

## 4.4 被拒对策

| 被拒理由 | 对策 |
|---|---|
| 类目不符 | 改「教育-在线阅读」+ 上传公版说明 |
| 业务域名未配置 | 回第 6 步 |
| 涉嫌版权 | 提交公版作品清单 + 来源链接 |
| 诱导分享 | 分享文案改中性 |
| 虚拟支付 | **iOS 端不能卖会员**，把会员入口隐藏 |

## 4.5 关键限制

**iOS 端小程序禁止虚拟支付**（微信 + Apple 双限制）。所以：
- 小程序适合做「免费读 + 拉新」
- 卖会员要引导到 App / 网页版
- 代码里已做适配：小程序环境下自动隐藏「导入书籍 / 网址导入」，并跳过 Service Worker
